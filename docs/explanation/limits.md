# Limits

The plugins track todo plans, OMP delegates and inherited Pi child processes. Kata's accepted close records determine completion. Session-local todo plans (kept only while Kata is unreachable) and pending close retries are saved in harness session entries and restored on resume.

- **Delegate discovery — host API.** OMP matches a delegation to a plan task by name, ref or word overlap, and to the active task only for an explicit current-task handoff; Pi does the same after inheriting `KATA_PI_PARENT`. Pi does not expose a general child-process spawn/join hook. Processes launched with a replaced environment, from another machine, or before parent startup finishes must receive an explicit binding. The native Pi attention registry is used to retain the parent's baseline before clearing inherited `KATA_REF`; compatibility is verified against the generated native adapter. **Upstream ask:** provide stable child identity, environment handoff, lifecycle receipts, and a public native-attention baseline API.
- **OMP native harness — Kata CLI.** Kata has no omp harness: `agent-hook contract omp` and `attention-native omp` are rejected, and `agent-hook install` has no omp target. The omp plugin passes `pi` to `attention-native`, which only selects payload parsing and the session token. **Upstream ask:** an `omp` harness for `attention-native`, `status` and `install` (user scope `~/.omp/agent/extensions/`).
- **OMP close transcripts — Kata client/server.** Kata 0.20.0 detects only Claude and Codex sessions and rejects `omp` in its transcript schema, including explicit `KATA_TRANSCRIPT_AGENT=omp` overrides. With close transcript attachment enabled, an OMP close can succeed while warning that the current session is unavailable or invalid. The plugin cannot truthfully attach an OMP transcript until Kata supports that identity. **Upstream ask:** native OMP session detection and validation across the CLI, daemon schema, and transcript links.
- **Shell attribution — by design.** Recognized standalone Kata commands receive the delegate's teammate; actor impersonation with `--as` is refused. Dynamic aliases and opaque embedded scripts must use the supplied binding command themselves. Lexical rewriting is not a security sandbox.
- **Observation and proof — host API / by design.** Tool observations cannot audit opaque programs' filesystem side effects. Missing receipts, unknown writes, failed checks, or incomplete reports can leave finished work open for review. Idle alone is not completion. **Upstream ask:** provide authoritative write-path and terminal verification receipts for opaque tools and delegated writers.
- **Session retention — host API / by design.** Durable OMP/Pi state requires a saved session and its custom entries; ephemeral sessions, deleted session files, or host compaction that discards those entries cannot restore local plans or retry queues. **Upstream ask:** preserve extension state across compaction and provide a larger durable state store with retention guarantees.
- **Outages and concurrent writes — Kata CLI.** Foreground hooks have bounded budgets. Outages are quiet and retryable, not proof that tracking succeeded. Concurrent external writers can race comments because Kata has no comment idempotency key. Guarded multi-key attention updates can partially succeed before a conflict; reopen has no atomic CLI guard. **Upstream ask:** add comment idempotency, atomic multi-key metadata updates, and revision-guarded reopen. Existing ownership/revision checks preserve conflicting writers' changes.
- **Abrupt termination — host API.** Graceful child shutdown can mark unfinished work for review; a crash or SIGKILL cannot run shutdown hooks. Saved retries resume when the harness session is reopened, rather than through an always-running background worker. **Upstream ask:** provide durable lifecycle delivery or launcher cleanup for terminated sessions.
