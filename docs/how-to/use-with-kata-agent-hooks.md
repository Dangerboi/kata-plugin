# Use with Kata agent hooks

Kata's native hooks (Claude Code uses them directly: `kata agent-hook install claude --attention`) provide contract/inbox context and optional session attention. This repository adds delegated issue tracking or todo plans. These plugins require Kata 0.23.0.

## Pi

```sh
kata agent-hook install pi --attention
```

The pi plugin checks the native adapter registry at prompt time. When a contract-enabled adapter covers the current folder, native code alone fetches and inserts contract/inbox sections. Otherwise, the plugin provides those sections. The `kata_todo` section is separate and other extensions' sections are preserved.

Kata 0.21's pi hook keeps child sessions off the lead's attention with `KATA_ATTENTION_HOST` and does nothing inside omp. Since 0.23.0 Kata gives that hook no contract outside folders with a `.kata.toml`, and the hook passes the session folder as `--workspace`. Hooks generated by an older Kata do not pass `--workspace` (and hooks from before 0.21 also lack the `KATA_ATTENTION_HOST` guard): after upgrading Kata, rerun the install command above and restart pi. The plugin leaves native attention to that hook and keeps the main process's `KATA_REF`. Child processes inherit the plugin's own parent marker (including the parent's provider, model and thinking level), receive a distinct teammate and their own assignment, and receive their contract in a folder with `.kata.toml`. A child still clears the inherited lead `KATA_REF` so its own assigned issue wins. Todo start/block operations still update their task's guarded attention; unfinished children request review on their own issues. See the [pi reference](../reference/pi.md).

## Oh-my-pi

Kata has no omp harness, so there is nothing to install. For a `KATA_REF` session the omp plugin checks the actor and teammate, then calls `kata agent-hook attention-native pi start|end` itself; pi is the closest harness and only selects payload parsing and the session token. Kata 0.21's pi hook does nothing inside omp (`pi.zod`), so a `PI_CODING_AGENT_DIR` shared with omp no longer adds a second attention writer. Do not install another session-attention writer for the same issue alongside it. Subagents receive their own binding and do not run the lead's attention transitions. Once attention starts, the lead also publishes Kata's `KATA_ATTENTION_HOST`, so a native Pi it starts from bash with the same `KATA_REF`, folder and daemon leaves its attention alone; a Pi started in another folder or on another issue tracks its own.
