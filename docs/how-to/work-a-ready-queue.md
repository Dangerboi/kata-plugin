# Work a ready queue under the plugin

This page covers only what the plugin adds when a lead works through `kata ready`. How to order the queue and write a hand-off is in the `kata` skill that tern-kata ships.

Every host's plan text says it too: delegate by putting the work in the plan, not by creating child issues for subagents to claim. The plugin claims each delegated issue and tells its delegate how to comment and close; the binding rules are in the [oh-my-pi](../reference/oh-my-pi.md#delegates), [pi](../reference/pi.md), [OpenCode](../reference/opencode.md#delegates) and [Claude Code](../reference/claude-code.md#delegates) references.

- **Skip session parents.** An issue labeled `omp-session`, `pi-session`, `opencode-session` or `claude-session` is a session's automatic parent ([metadata](../reference/metadata.md)). It is not work: an automatic parent closes from its children's evidence once they are all closed ([closing rules](../reference/closing-rules.md)).
- **Skip plan tasks another session holds.** A plan task another lead session started or blocked stays that session's (`todo.session`) while it is open, and ops on it from your session are refused. Leave it unless the user says that session crashed or was killed; only then take it over, with the user's `/todo takeover <task>` on omp or `takeover: true` elsewhere ([closing rules](../reference/closing-rules.md)).
- **Review and resume a delegate's hand-back.** A delegate that exits with its issue still open hands it back to you labeled `needs-review`, with a comment saying it did not close the issue. While the issue still carries the delegate's teammate, `work.attention` also reads `needs-human`, with a message such as `Subagent <name> completed without closing its issue; review its report and verification.` That flag is the plugin's, not a question for a person: read the delegate's report, then close the issue with your own evidence or delegate it again. Your accepted close of a plan task removes `needs-review`.
- **Name one item or ticket per brief.** A delegate's brief names exactly one plan item or ticket, and no sibling's ref or title. A sibling's title of three or more words counts as naming it, so a brief that also mentions one names two, and the spawn is refused ("Name one ticket per task and split the work across tasks").
