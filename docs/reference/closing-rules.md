# Closing rules

Kata is the final validator. Todo `done` requires a substantive message of at least 40 characters and typed evidence. Kata shows a close message only as the close reason, so `done` also comments `Done: <message>` and the evidence on the plan task in the same close call. Wontfix retirement requires a task-specific reason of at least 60 characters. The displayed task becomes completed or abandoned only after Kata accepts the close. Throttled closes remain pending and retry only while their saved issue revision and requested action still apply. A valid instruction replacing that task’s intent cancels a superseded retry. Re-listing the same task preserves a promised completion; explicitly keeping a task cancels its pending removal. Starting another task or rejecting invalid input preserves the promised close; unavailable or rejected evidence is never invented.

OMP and Pi check the current actor, exact teammate, and issue revision before task changes, including completion, retirement, and replay. A rejected ownership or revision check preserves the other writer’s state. Session-local plans (kept only while Kata is unreachable) skip Kata writes until they replay; a Kata project whose name starts with `local-` still requires normal ownership and evidence.

A plan item a lead session started or blocked belongs to that session (`todo.session`) while it stays open. Another lead session on the same plan parent is refused on it even with the same actor and teammate: two sessions of one user without `KATA_TEAMMATE` no longer change each other's work. A fork counts as its source, and a resumed session as itself. Nothing tells the plugin whether the other session still runs, so another lead takes an item over only on request: `takeover: true` on `start`, `done`, `drop`, `rm`, `block` or `unblock` naming the item, or a `/todo` command, which the user runs. The takeover comments `Taken over by session <new> from session <previous>` on the issue first, then moves the marker. Pending items, closed items, ticket items and items created before this rule keep the actor and teammate check alone. `init` with `replace: true` refuses to drop an item another session holds.

An automatic parent closes only when every current Kata child is closed, required delegation has finished, and the adapter's settlement barriers are satisfied. The adapter bounds the close audit by the current children’s close times, reads each exact close event, unions its typed evidence (`attachment` evidence is left out, because Kata accepts an attachment only when it is linked on the issue being closed; a parent whose children gave only attachments stays `needs-review`), then rechecks the parent’s ownership, membership, and revisions before the guarded parent close. Wontfix children count as closed but supply no proof. Missing/empty evidence or a rejected union leaves the parent open with `needs-review`. Explicit parents never auto-close. New work may reopen an automatic parent.

OMP and pi delegates close themselves. Each bound delegate is told to comment on its issue what it did, how it verified it and what remains before it finishes, closed or not, so an issue several delegates worked carries one comment per delegate. A delegate that exits without such a comment (none under its teammate, not counting a report the plugin posted for it earlier) gets its report posted for it, under its teammate and headed `Report from subagent <name>` (an omp subagent's name, a pi child's name as the [pi reference](pi.md) describes): its last assistant text, or what it yielded, cut at 4000 characters. One that finishes without closing hands its plan task back to the lead with `needs-review`, and the lead's own accepted close then removes the label. Automatic-parent completion in every adapter trusts Kata close records and never reconstructs proof from shell commands.
