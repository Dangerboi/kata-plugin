# Pi reference

Package: `@dangerboi/kata-pi` on npm; portable entry: `plugins/pi/kata.ts`. The repository root has a `pi.extensions` shim for Git installation. Pi supplies TypeBox and its extension API through declared peers. The entry exits under OMP before loading TypeBox. Requires Kata 0.21 or later; the minimum version is documented rather than runtime-gated, as with the existing Kata requirement.

| Event/surface | Behavior |
| --- | --- |
| `session_start` | Restore saved plans/retries or child binding; a child clears the inherited lead `KATA_REF`. Export the child-process marker, plus `KATA_TRANSCRIPT_AGENT=pi` and `KATA_TRANSCRIPT_SESSION_ID`; a child replaces the pair it inherited. |
| `session_tree`, `session_shutdown` | Reload/drain reconciliation; a child that exits with its issue open restores it (no tool run) or hands it back for review. `session_shutdown` leaves the transcript variables alone: a reload or new session starts the next instance in the same process, and that instance's `session_start` overwrites the pair. Clearing at shutdown could delete the new pair after a slow cleanup. |
| `before_agent_start` | Bind inherited child work, inject its contract and exact issue/teammate/close command, or add the main plan and fallback context. |
| `agent_before_settle` | Add a hidden continuation for actionable unfinished main work, within a three-reminder progress budget. Questions, blockers, aborts and errors suppress it. |
| `tool_call` | Ensure a parent before a Bash command that launches `pi`; mutate Bash input in place to route bare `kata` and enforce child teammate attribution. Refuse child `--as`. |
| `tool_result` | Observe successful standalone main claims; ignore failed results. |
| `registerCommand("todo")`, `input` | Provide `/todo` and visible command replies. |

`KATA_PI_EXECUTABLE` selects the executable, falling back to `KATA_OMP_EXECUTABLE`, then `kata`. Debug output uses `KATA_PI_DEBUG`, with `KATA_OMP_DEBUG` as fallback. Existing actor identity is preserved. Explicit executable paths and quoted data are not rewritten.

Main sessions export `KATA_PI_PARENT` with their process/session identity, qualified parent ref, workspace, and teammate seed. After `kata move`, a child started with the old ref re-pins it. A child Pi process inherits that marker, retains the actor, derives a distinct teammate, and sets its own inbox recipient. A child prompt is matched against every open child of the parent with the same rules as OMP: an exact title, qualified ref or bare short id, then a clear word overlap; the lead's active task only for an explicit "current task" handoff; a prompt that names two tickets or plan items, or matches none, or whose named task is already delegated or owned by another writer, is an untracked delegate: it creates no issue, gets the untracked context (it has no Kata issue and must not create, claim or close issues; reading is fine) and its `kata` calls are still rewritten with its teammate. An assigned child works its issue through the shared delegate lifecycle: claim through the ownership checks, its teammate, `pi.subagent_id`, `pi.session_id`, `todo.status` in progress and `work.attention` ok; its own `todo` plans under that issue. Its binding tells it to comment on the issue what it did, how it verified it and what remains before it finishes, closed or not. A child that exits having run no tool restores the issue (claim, teammate, status, attention and subagent key, no `needs-review`); one that ran a tool and left the issue open comments, sets `work.attention` to needs-human and hands it back (`needs-review`, an inbox request, the task back on the lead's teammate). The record lives in the child's session branch, so a resumed child keeps its assignment. A `KATA_TEAMMATE` the lead set for the child is kept. A child started without `--model`, `--models` or `--provider` switches to the parent's provider and model (and thinking level, unless `--thinking` is given). Revision guards prevent two children from taking the same task. Main todo mutations cannot complete delegated tasks: the child closes itself and `view` reloads Kata state. Saved child bindings retain identity when resumed. Child shutdown has a 3 s budget for the rollback or hand-back above. A `reload` is not an ending and changes nothing.

The main process retains `KATA_REF` and its explicit plan binding. Kata 0.21's native adapter owns session attention, uses `KATA_ATTENTION_HOST` to keep child sessions off the lead's attention, and skips OMP hosts. A hook generated by an older Kata lacks that guard; rerun `kata agent-hook install pi --attention` after upgrading Kata. The plugin leaves native attention baselines alone. A child still clears the inherited lead `KATA_REF` so its own assigned issue takes precedence. Use the qualified ref of its assignment for child scripts rather than assuming inherited `KATA_REF`. The native registry controls [contract coexistence](../how-to/use-with-kata-agent-hooks.md); children always receive their own assignment and contract.

Todo operations match the [OMP plan](oh-my-pi.md), including where the plan lives (`KATA_DEFAULT_PROJECT` with a repo label, else the inferred project), the lazy session parent, and replay after a Kata outage. Session-local plans (kept only while Kata is unreachable) and pending close retries persist in session custom entries and resume with the saved session. Children manage their own issues instead of mutating the main todo plan. Automatic parents reconcile from actual Kata children and accepted close evidence; explicit parents remain the lead's responsibility. See [closing rules](closing-rules.md) and [limits](../explanation/limits.md).

Typing `#` plus part of a ticket id or title word in the interactive editor offers matching open Kata issues beside Pi's own items; accepting inserts the qualified ref (`kata-plugin#bc7q `). Behavior, scoping (`#<project>#<token>`, `KATA_DEFAULT_PROJECT`, digits-only tokens left alone) and the never-block-typing rule match the [OMP reference](oh-my-pi.md#ticket-references-in-the-prompt). Pi receives `#` as an added trigger character; only the interactive main session registers it.

Items that name a ticket (`<project>#<short_id>: <action>`) work and log on that ticket exactly as in the [OMP plan](oh-my-pi.md), including the no-parent plan. Pi child processes do not bind such items: a child still follows the matching rules above.

The inbox is read per turn only: `kata inbox --for <address> --json` runs before each prompt, and a request sent while the agent is idle or mid-run waits for the next prompt. Live delivery from `kata events --tail` is OMP-only, because Pi's `sendUserMessage` has `steer` and `followUp` but no delivery that starts a turn when idle and joins a running one at a step boundary without interrupting its tools. Under Kata's native pi adapter (`kata agent-hook install pi --attention`) this plugin skips the inbox read and Kata inserts the inbox itself, so the own-actor sender filter does not apply.
